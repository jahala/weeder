An audit gates the `verified` status; nothing else can flip a feature green. Implementation and verification track separately, so 100% steps done never reads as done until the checks pass.
+Loops and evals, for agents. Impeccable self-briefing pages, for humans. A pass that only a verifier can write, for trust that survives handing the file to a stranger.
 
----
+A loop is a goal with a fitness function: `## Tests` are checks a machine, a judge, or a human can close; `## Tried` is append-only memory so nothing gets re-attempted; state (`done` / `failing` / `needs-you` / `open`) is derived from the check boxes on every read and never hand-set. One markdown payload inside a tiny HTML shell renders itself in a browser at `file://` with no server, and the same file is the complete work order a build loop hands to a worker. Full contract: [`loop/FORMAT.md`](./loop/FORMAT.md). Full system doc: [`loop/ARCHITECTURE.md`](./loop/ARCHITECTURE.md).

-## How it works
-
-Each `.tend.html` file is a polyglot artifact: valid HTML that renders in any browser, valid bash that exposes a `data` verb returning the feature's JSON, and an MCP-editable source of truth — all in one file. No server, no build step, no separate data store.
-
-Features are structured as bets with three interlocked threads:
-
-```
-PRODUCT thread       VALUE thread         TECH thread
-  what  ←──────────── fit  ─────────────→  where
-  why   ←──────────── impact ────────────→  how
-```
-
-Each slot is a one-line claim. Slots constrain each other — WHY without WHAT is a complaint; IMPACT without HOW is wishful thinking. Checks anchor each slot: `validates: <slot>` + a `method` (`synthetic-test | code-review | user-report | analytics-metric | agent-judgment`). Personas (ICP archetype + Klement Job Stories) and opportunities connect features to the humans they serve. When every check in a feature's audit passes, the feature reaches `verified` — that is the one hard gate.
-
-The same bet shape applies at every level: the garden (project bet), features, and child features that drill into a specific parent check.

-### When something feels off
+`run` already verified it — but `verify` is also a direct command, and re-running it is always safe: a fresh stamp is a no-op, a stale one re-opens the check.
 
 ```bash
-tend doctor          # diagnose common issues
-tend doctor --fix    # repair the mechanical ones (snapshots, polyglot partials)
+node loop/dist/cli.mjs verify greet.loop.html --repo-root .
+# greet.loop.html:c1 skipped-fresh
 ```
 
-`tend doctor` is advisory — it always exits 0. The `--fix` flag rebuilds the feature index and syncs partials; issues that need a human (broken graph refs, stale audit evidence) are reported, not silently patched.

-### Audit evidence
-
-`evidence_path` should point at executed outputs — a test run log, a command's stdout capture, a screenshot. Pointing at a source file is not evidence; it tells tend *where* the code is, not that it *works*. The audit mock-detection flags this and prevents `verified`.

-## What tend is NOT
-
-- **Not a ticket tracker.** Tend maps feature bets at the strategic level. It does not track bugs, sprints, or day-to-day tasks. Adapters bridge to Jira/Linear/GitHub Issues.
-- **Not a documentation tool.** Filling slots to prove diligence is theater. Tend's job is to direct energy, not manufacture activity around it.
-- **Not a SaaS.** No accounts, no server, no lock-in. Files live in your repo and survive every context window.
-- **Not multi-writer safe (yet).** Concurrent writes to the same polyglot = last-writer-wins. Atomic file writes prevent corruption, not update loss.
-- **Not for every project shape.** Tend fits problem-solving software with AI agents in the loop. Pure note-taking, brochureware, and art projects can use the polyglot format but may find the methodology mismatched.
-

+## Using tend in your own project
+
+### Where things live
+
+| What | Lives at | Created via |
+|---|---|---|
+| Feature | `docs/tend/features/<id>.tend.html` | `tend_create_feature` (MCP) |
+| Persona | `docs/tend/features/<id>.tend.html` | `tend_update_catalog` (MCP) |
+| Opportunity | `docs/tend/features/<id>.tend.html` | `tend_update_catalog` (MCP) |
+
+Personas and Opportunities are catalog entries, not standalone features. There are no `docs/tend/personas/` or `docs/tend/opportunities/` directories — everything is a polyglot in `docs/tend/features/`.
+
+### Starting fresh (greenfield)
+
+```
+/tend position   →  define who it's for (ICPs + Klement Job Stories)
+/tend brainstorm →  shape features (slots + checks)
+/tend plan       →  write test-first steps
+/tend run        →  execute
+/tend audit      →  verify checks; gate verified
+```
+
+For an existing codebase, run `/tend discover` first to document what's already built.
+
+### Source directories (`source_dirs`)
+
+Tend's coverage, audit-evidence paths, and narrative cite-checks need to know where your code lives. By default it looks in `src/`, `schema/`, `skills/`, `templates/`, and `scripts/`. If your code lives elsewhere (e.g. `petals/`, `lib/`, `packages/`), set `source_dirs` in the garden's `oo-data`:
+
+```json
+{ "source_dirs": ["petals"] }
+```
+
+`tend init` auto-detects the top-level directories in your repo and scaffolds `source_dirs` for you. If coverage checks report zero hits, the error message names the configured roots and tells you which field to update.
+
+### When something feels off
+
+```bash
+tend doctor          # diagnose common issues
+tend doctor --fix    # repair the mechanical ones (snapshots, polyglot partials)
+```
+
+`tend doctor` is advisory — it always exits 0. The `--fix` flag rebuilds the feature index and syncs partials; issues that need a human (broken graph refs, stale audit evidence) are reported, not silently patched.
+
+### After upgrading tend-cli
+
+The MCP server caches code, not data. After `npm upgrade tend-cli` (or `npm run build` if you work in the repo), restart the MCP server:
+
+```bash
+pkill -f 'tend-cli serve'
+# then re-open Claude Code / your agent to reconnect
+```
+
+Running a stale server against updated data types is the most common source of confusing write errors.
+
+### Audit evidence
+
+`evidence_path` should point at executed outputs — a test run log, a command's stdout capture, a screenshot. Pointing at a source file is not evidence; it tells tend *where* the code is, not that it *works*. The audit mock-detection flags this and prevents `verified`.

+## What tend is NOT
+
+- **Not a ticket tracker.** Tend maps feature bets at the strategic level. It does not track bugs, sprints, or day-to-day tasks. Adapters bridge to Jira/Linear/GitHub Issues.
+- **Not a documentation tool.** Filling slots to prove diligence is theater. Tend's job is to direct energy, not manufacture activity around it.
+- **Not a SaaS.** No accounts, no server, no lock-in. Files live in your repo and survive every context window.
+- **Not multi-writer safe (yet).** Concurrent writes to the same polyglot = last-writer-wins. Atomic file writes prevent corruption, not update loss.
+- **Not for every project shape.** Tend fits problem-solving software with AI agents in the loop. Pure note-taking, brochureware, and art projects can use the polyglot format but may find the methodology mismatched.

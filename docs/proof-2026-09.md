# proof — the harness hooks, run for real

`weed hook <claude|gemini|codex>` reads a harness hook event as JSON on stdin and
answers in that harness's own shape. The integration tests in `tests/hook_*.rs`
hold weed to the shapes; this file holds it to the harnesses, by recording what
happened when a real session ran with weed wired in.

## Where weed stands

Two moments, in every harness:

| moment | claude code | gemini cli | codex | what weed does |
| --- | --- | --- | --- | --- |
| a tool call still refusable | `PreToolUse` | `BeforeTool` | `PreToolUse` | judges the index where the command runs `git commit`, and denies with the table as the reason |
| the turn trying to end | `Stop` | `AfterAgent` | `Stop` | judges the working tree, and blocks the stop with the table as the reason |

A commit that carries `--no-verify`, `-n`, or `-c core.hooksPath=…` is denied
without judging anything: it asked for nothing to be judged.

Every judgement runs `weed check --strict`, so an allowance an agent wrote for
itself is reported and not honoured. That has one consequence worth writing down:
the `Weed-allow:` trailer of the commit being prepared changes nothing a hook
decides, because `--strict` gives a suppressed finding its own level back. weed
therefore does not lift the message out of the `git commit` command line — there
is nothing for it to change, and plumbing that cannot alter an outcome is
plumbing no test can hold.

## The exit code a hook leaves with

weed's contract is 0 clean, 2 at least one block-level result, 3 weed could not
run. `weed hook` keeps 0 and 2 and does not use 3, and the reason is that a
harness reads a hook's exit code as its own protocol:

| harness | 0 | 2 | 3 |
| --- | --- | --- | --- |
| claude code | the answer on stdout is read | refused, stderr is the reason | a non-blocking error: the tool call runs, the turn ends |
| gemini cli | allowed | refused, the text is the reason | refused |
| codex | the answer on stdout is read | refused, stderr is the reason | the hook is reported as failed |

Leaving with 3 on Claude Code would let the commit through. A gate that could not
judge has to refuse to stay a gate, so `weed hook` refuses at 2 and says on the
same line that it could not judge. Both channels carry the reason — the harness's
own JSON on stdout and plain lines on stderr — so the refusal does not depend on
knowing which of the two a given harness reads.

Where there is no repository at all, weed passes through in silence. A turn can
end anywhere, and holding one hostage to a directory nobody asked weed about
would make the hook a nuisance rather than a gate.

## codex — what a hook may refuse

Codex ships a JSON schema for every hook event's input and output inside its own
binary (`codex-cli 0.133.0`, read from the vendored `bin/codex`). Those schemas
say plainly which events carry a decision. Four carry none: a hook wired to one
of them is run and heard, and cannot refuse anything.

| event | codex's output schema | weed |
| --- | --- | --- |
| `PreToolUse` | `permissionDecision: deny` | denies a `git commit` over an index that blocks, and denies a bypass outright |
| `PermissionRequest` | `decision: deny` | passes through |
| `PostToolUse` | `decision: block` | passes through |
| `UserPromptSubmit` | `decision: block` | passes through |
| `SubagentStop` | `decision: block` | passes through |
| `Stop` | `decision: block` | blocks a turn that ends over a tree that blocks |
| `PreCompact` | no decision | one line, and no answer |
| `PostCompact` | no decision | one line, and no answer |
| `SessionStart` | no decision | one line, and no answer |
| `SubagentStart` | no decision | one line, and no answer |

Codex accepts only `deny` from a `PreToolUse` hook — `allow` and `ask` are
rejected as unsupported, and a `deny` without a non-empty reason is rejected too.
weed writes the reason and stays silent where it has nothing to refuse, which is
the whole of what codex will take.

The line weed prints at an event codex takes no decision from names the event and
says where the hook belongs instead:

```
codex takes no decision from a PreCompact hook, so weed judged nothing here. wire weed hook codex to PreToolUse and Stop, the events codex lets a hook refuse.
```

`tests/hook_codex.rs` reads the table above back out of this file and holds weed
to it in both directions: every event this table calls deaf gets that line, and
every event it does not gets silence.

## claude code — the stop hook, run for real

### 2026-09-05 — 2.1.261 (Claude Code), weed 0.1.0

Both halves ran `claude -p` in a temporary repository with the Stop hook
pointed at `weed hook claude` through `--settings`, on model `haiku`.

**Refused.** The working tree carried a half-finished merge:

```
error  G1  src/parser.ts:2  a merge conflict marker (<<<<<<<) was added.
error  G1  src/parser.ts:4  a merge conflict marker (=======) was added.
error  G1  src/parser.ts:6  a merge conflict marker (>>>>>>>) was added.
3 errors, 0 warnings, 0 notes
```

The session tried to end and was sent back. The proof stopped it as soon
as the block reached the transcript; left alone the hook refuses every
stop over the same tree, so the turn cannot end at all. This is what the
session received, verbatim:

```
Stop hook feedback:
error  G1  src/parser.ts:2  a merge conflict marker (<<<<<<<) was added.
error  G1  src/parser.ts:4  a merge conflict marker (=======) was added.
error  G1  src/parser.ts:6  a merge conflict marker (>>>>>>>) was added.
3 errors, 0 warnings, 0 notes
weed hook refused: the working tree carries a finding that blocks, and a turn that ends here ends over it. repair what the table names, then say the work is done.
```

**Allowed.** The merge finished, and weed had nothing to say:

```
0 errors, 0 warnings, 0 notes
```

The session ended on its own, exit 0, with no Stop hook feedback at all.

## gemini cli — the after-agent hook, run for real

`scripts/proof/gemini-stop.sh` writes what happened here. It is the owner's to
run: `~/.gemini/settings.json` on this machine carries no auth type, so no worker
can start a real Gemini session from it.
